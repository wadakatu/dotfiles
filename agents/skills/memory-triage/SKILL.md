# memory-triage

memory は書き足される一方で腐る。定期的に棚卸しして「rules に昇格すべきもの」「消すべきもの」を整理するスキル。

## トリガー

- ユーザーが「memory の棚卸し」「メモリ整理」を依頼したとき
- memory 内に「rules へ昇格済み、削除可」と自己申告している項目を見つけたとき（報告して棚卸しを提案する）

## 実行手順

1. **走査**: 対象プロジェクトの memory ディレクトリ（MEMORY.md + 各ファイル）を全読する
2. **分類**: 各メモリを以下に分類する
    - **昇格候補**: 繰り返し参照される普遍的なルール → `.claude/rules/` または CLAUDE.md への昇格を提案
    - **昇格済み**: すでに rules / CLAUDE.md に反映済み → 削除候補
    - **陳腐化**: 参照先のファイル・機能・前提が消えている → 削除または更新候補
    - **重複**: 同内容のメモリが複数ある → 統合候補
    - **現役**: そのまま維持
3. **提示**: 分類結果を一覧で提示する（ファイル名 + 分類 + 理由1行）。**この時点では何も変更しない**
4. **実行**: ユーザーが承認した項目**のみ**、削除・統合・昇格を実行し、MEMORY.md の索引を更新する

## アンチパターン

- 承認前にメモリを削除・移動する
- 「古そう」という印象だけで陳腐化と判定する（参照先の実在を確認してから判定する）
- 昇格時に内容を要約しすぎて **Why**（なぜそのルールになったか）を落とす
- 昇格と削除を1手でやって差分を追えなくする（昇格 → ユーザー確認 → 削除の順）
