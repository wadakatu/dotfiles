# /catch-up

持ち主は、この `/catch-up` の前に自分で打った最後の発言までを覚えていて、その後のことは何も知らない、として書く。通知・サブエージェントの報告・hook が差し込んだ文は、持ち主の発言ではない。圧縮で元の発言が見えないときは、要約に在る最後の依頼を起点にし、そう断る。

報告を書き終えるまでは読むだけ（コードを変えない・起動しない・投稿しない。判断を聞くときのカードの移動は除く）。答えをもらった後は通常どおり動く。このセッションが触った PR・CI・エージェントの今の状態は、読み取りのコマンドで確かめてから書く。

1. **1 文目**: 持ち主を待っているものが在るか、無いか。何も起きておらず、何も待っていなければ、そう書いて終わる。
2. **変わったこと**: 頼まれたこと 1 つにつき 1 行。どうなったかと、今の状態（済んだ／動いている／失敗した／確かめていない）。持ち主にとって何も変えなかった作業は書かない。
3. **判断待ち**: 持ち主にしかできないもの（仕様の選択・承認・戻せない操作・自分に無い権限）を全部、先に要る順に。「ほか n 件」に畳まない。1 件ごとに、リンク／選ぶと何が変わるか／根拠／リスク（低くても書く）／推奨。分からない項目は「不明」と書く。自分で進められる作業は入れない。
4. 自分で続けられる残りの作業が在れば、最後に 1 行。

書き方はグローバルの指示の「応答」と「委任の線引き」（質問の書き方）のとおり。ただし、この一覧は分けずに全部出し、1 件ごとの推奨は 1 行でよい。加えて、hash・パス・コマンド・件数は、持ち主が動くのに要るものだけにし、PR・ブランチ・エージェントは持ち主が知っている名前で呼ぶ。
一覧は読むためのもので、質問で終えない。まだ聞いていない判断が在れば、一覧の後で、先に要るもの 1 つを AskUserQuestion で聞く（そのときのカードの移動は、グローバルの指示の決まりどおり）。
