# リポジトリの規約を「小さいから」で省かない

- `.claude/rules/` などに明文化されたレイヤ構成（例: リクエストの検証 → 引数オブジェクト → サービス → レスポンスの変換）を、
  「ロジックが小さいから過剰」という理由だけで省略しない
- 省くのは「規約と技術的に両立しない」ことを示せる場合だけにする。そのときは理由をコードの docblock と PR 本文の両方に残す
- 判断が割れるときは、先に選択肢を出して聞く

**Why:** 小さな機能でコントローラに分岐と文言を全部書いたところ、「なぜコントローラに全て詰め込んでいる？」と指摘されて作り直した。
規約は各クラスの行数ではなくレイヤの責務境界を決めるもので、「今回は小さい」は省略の理由にならない。
省略の判断はレビュワーから見ると規約違反にしか見えず、毎回説明が要る。
技術的に両立しない例: レスポンスを変換する層が必ず `{data: ...}` で包むため、外部サービスが要求する `{response_type, text}` の形と両立せず、
その層だけは作らなかった。ほかの層にはそういう理由が無かったので作るべきだった。
