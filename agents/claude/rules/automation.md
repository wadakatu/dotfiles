# 手作業と毎回の承認を残さない

## 毎回の手順を人の手作業に残さない

- 「毎回 X してください」と書きそうになったら、X を自動化の経路（setup script など）に入れられないかを先に検討する。
- 省く理由が「重い / 失敗するかも」なら、実測してから判断する。
- 意図的に省くなら、省いた理由と入れる場合の案を同じ回答に書き、ユーザーに選ばせる。黙って手作業に倒さない。

**Why:** 自動化の受け皿を作った直後に毎回の工程（build・setup）を手作業に残したら、「毎回私が実行するんですか？」と返された。省いた理由はどれも毎回手で打つより軽い問題で、実測すると全工程 1 分半ほどで完走した。

## ローカルの検証は人の承認を挟まずに進む形にする

- 使い捨て環境の作成・build・API を打つなどのローカルの検証は、すぐ「人が毎回承認」にしない。
- 危険がある操作は、レビュー済みの入力（origin/main と同じ build 入力など）に限る条件を探し、その条件の下で許可の規則に入れる案を勧める。
- 条件を満たさないものは、人を呼ばずに「比較不能」などの機械の判定に倒す。

**Why:** build を「許可の規則に入れない（毎回人が承認）」と勧めたら、「なぜ入れない方がよい？　基本ローカルの検証は自動で進むようにしたい」と返された。
