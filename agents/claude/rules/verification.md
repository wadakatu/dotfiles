# 検証

## 退化した本番状態で選択ロジックを検証したことにしない

- 選ぶ・絞る・順序に依存するコード（`jq` 式や `--format` も）は、本番で正しい値が返っても選択の検証にならない（本番は要素 1 つなどに退化しがち）。
- 合成入力（`echo '<JSON>' | jq -r '<式>'`）も通す。候補 2 つ以上・境界値・キー欠落を必ず含める。
- ドキュメントに書くコマンドは書いた形のまま実行する。

**Why:** `status.traffic[0]` を 1 要素の本番で確かめたが、canary が percent 0 で入りうる。

## コンテナで動くアプリの挙動はそのコンテナで確かめる

- docker で動くアプリはそのコンテナの中で確かめる（compose ラッパー経由の `exec -T <service> …`、スクリプトは stdin）。ホストの Herd PHP は版が違い、参考にしかならない。
- ランナー回避の規則は権限の抜け道を防ぐため。環境を揃えるときはコンテナで実行し、流した場所をコマンドで見せる。
- 同じ作業でホストとコンテナを混ぜない。

**Why:** ランナー回避を理由にホストの PHP で実験し、「なぜdockerを使わない？」と聞かれた。
