# サブエージェントを並列に回すとき

worktree 分離のサブエージェントを並列に回すときは、ディスパッチのプロンプトに最初から次を入れる。

- 作業ファイルは `<scratchpad>/<エージェント固有の名前>/` に置かせる。サブエージェントはセッションの scratchpad を共有するので、
  `pr_body.md` や `feature.log` のような汎用名は他のエージェントに上書きされる（他人の件数を自分の結果として報告しかけたことがある）
- テスト DB などの共有資源は、設定ファイルで固定されていないかを確かめてから、エージェントごとに分ける。
  env の export が設定ファイル側の固定に負けて、同じ資源を奪い合うことがある
- ファイルを消したら autoloader / classmap を作り直させる（PHP なら `composer dump-autoload`）。消したクラスが残ってテストが落ち、変更のせいと誤認しやすい
- 同時に `git switch -c` すると `.git/config` のロック競合で upstream の設定だけ失敗することがある（push 時に直る）

報告されたテスト件数は参考値として扱う。検証の本線は、CI の緑と、全ブランチを merge した統合 worktree での全ゲートの実行にする。

**Why:** 並列の速さが、偽の赤・他人の件数の取り違え・余計な調査と訂正メッセージで相殺された。
