# 設計案の出し方

案や推奨を書くとき（承認を求める場面に限らず、報告の中の推奨や実装途中の設計選択も）は、公式ドキュメントとフレームワークの実装まで当たり、標準のやり方と自分の案の差を先に示す。

- 使う API が公式ドキュメントどおりか（URL 付き）
- フレームワーク自身の扱い（vendor を読む）
- 標準から外れる点と、外す理由（rules・前例）
- 運用・セキュリティ方針は、規格に加え主要サービスの実例を一次資料で集め、照らしてから聞く

**Why:** 承認を求める場面に限った書き方では、報告の中の推奨で「ベストプラクティスに沿っていますか？」と後から聞かれ続けた。
