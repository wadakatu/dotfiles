# 実装・依存の置き換えは実データ規模で計測してから

ライブラリやアルゴリズムを別の実装へ置き換えるとき（例: `fast-deep-equal` → lodash の `isEqual`）は、挙動の一致だけで判断しない。
速度を実データに近い大きさで計測してから PR にする。

- 置き換える対象の呼び出し箇所が、描画・入力・一覧などのホットパスかを先に確かめる（参照の一致で打ち切れない比較、毎回作られるオブジェクトなど）
- 小・中・大の大きさ別に、1 回あたりの時間と比を表で出す。呼び出し頻度を掛けた上乗せの見積もり（フレーム予算 16ms との比較など）まで示す
- テストのデータは小さいので、テスト実行中の合計時間は判断の根拠にしない
- 同じ用途のライブラリが 2 つあるように見えても、速度を理由に意図して選んだ可能性がある。リポジトリの設計メモや ADR を先に確かめる

**Why:** 依存を減らす整理で、deep equal のライブラリを lodash の `isEqual` に置き換えた PR を出した。テスト中の合計時間（2.8ms 対 5.9ms）だけを見て
「体感できる差ではない」と書いたが、実データ規模では lodash が 2.6〜4.1 倍遅く、エディタの描画経路のキャッシュ判定で後退になるため PR を閉じた。
ユーザーからは、これからは計測もするよう求められた。
