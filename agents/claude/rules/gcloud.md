# gcloud と auto mode の分類器

- 書き込み系の gcloud と、読み取りでも `secrets versions access`・本番の `secrets versions list` は分類器に止められる。本番の secret は最初からコマンドを示し、`!` で実行してもらう。
- 実機検証は、読み取りは自分で、書き込みは 1 本のスクリプトにして `! bash <path>` で実行してもらう前提で組む。スクリプトには:
  - 危険な前提が崩れたら中断する
  - 一時的に変えた定義は `trap ... EXIT` で必ず戻す
  - 判定に使う証跡を出力する

**Why:** 止められてから手順を組み直す二度手間になった。

## 本番シークレットの値は読まない・聞く前に調べ切る

- 本番の secret は、存在の確認（`gcloud secrets list` の名前）までにする。値は、分類器に止められなくても自分では取らない。
  本番のキーを使って外部 SaaS の API を叩く案も、自分からは出さない。読み取り専用の API でも同じ。
- ユーザーに聞く前に、読み取り専用の `gcloud ... describe` / `list` で取れる事実を取り切る。実測値を示し、それでも残る
  人にしか答えられない部分だけを聞く。
- 聞くときは「自分で確認できた範囲」「承認が要る範囲」「技術的に確認できない範囲」を分けて示す。

**Why:** 外部 SaaS の IP 許可リストへの依存を確かめるため、本番の API キーで読み取り専用 API を叩く案を出したところ、明確に禁止された。
本番の secret の値は、コンテキストに載った時点で漏洩面が増える。同じやり取りで、自分の権限で調べられることを先に聞いてしまい、
「自分では確認できないのか」と返された。自分で確認できることを聞くと、ユーザーの手を止めるだけになる。
