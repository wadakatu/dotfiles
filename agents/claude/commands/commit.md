# /commit

変更内容を適切な粒度でコミットする

## 処理フロー

1. **現在のブランチを確認**
    - 現在のブランチに対してコミットを行う
    - 現在のブランチが default ブランチ または 保護されたブランチの場合は新しくブランチを作成する（`feature/xxx` `fix/xxx` など機能ベースのプレフィックスのみ。人名プレフィックスは付けない）

2. **変更ファイルの解析**
    - `git status` / `git diff` で変更されたファイルと内容を確認
    - 関心事が混ざっている場合は適切な粒度で複数コミットに分割する

3. **コミットメッセージの決定**
    - 既定は **英語の Conventional Commits**（`feat:` `fix:` `docs:` `refactor:` `chore:` 等。破壊的変更は `!` を付与）
    - 対象リポジトリの CLAUDE.md / プロジェクトコマンドに明示規約がある場合は**そちらを優先**する。迷ったら `git log --oneline -10` で直近の実例に合わせる
    - `Co-Authored-By: Claude ...` などのトレーラーは付けない
